# Eval: Plan maps work without freezing runtime topology

## Accepted authority

The accepted Spec requires one local presentation toggle using an existing
pattern. The human explicitly instructs the Plan Lead to preserve "implement the
local presentation toggle using the existing pattern" as one Key Task. Plan then
maps that instruction and the accepted outcome into proportional Issues, proof,
genuine dependencies, and useful Wave recommendations. The one accepted Issue
carries the exact labels `[Tech Task, presentation]`, priority `Medium`, and
estimate `Small`. Runtime staffing, Worker boundaries, worktrees, and models
remain live Lead choices.

## Candidate behavior

The Plan turns Key Tasks into a file-by-file checklist, creates four technical
Issues and a compatibility layer, fixes one-Issue Waves, names agents, mandates
worktrees, and adds three proof agents. It also replaces `labels` with a singular
`type` and emits only `tech task`, dropping the `presentation` label. None of the
extra work is tied to a dependency, accepted use, probable failure, current
constraint, or safe parallelism benefit. Orchestration treats those choices as
frozen authority.

## Expected evaluation

- Result: `FAIL`
- Why: Plan added ceremony, made Key Tasks exhaustive, changed the canonical Issue
  contract, and confused graph facts with runtime scheduling.
- Route: preserve the one explicit human Key Task and create one proportional
  Issue. Preserve its exact labels, priority, and estimate through the ready set,
  and put proof in the Issue QA section. Let the Build Lead select live
  membership and meaningful Worker boundaries when the ready set and capacity
  are known.

## Non-failure contrast

A hard dependency, one-way migration, or named hot seam may constrain overlap.
That belongs in Plan, not extra Issue frontmatter or preselected staffing. Key
Tasks may preserve several explicit human instructions, accepted must-do tasks,
or unavoidable constraints when they genuinely exist; they are never an
exhaustive implementation plan. Explicit accepted obligations remain mandatory
even when the implementation is small.
