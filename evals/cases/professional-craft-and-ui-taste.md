# Eval: Professional craft and UI taste stay inside authority

## Accepted authority

The Spec requires a small interactive UI using the repository's existing design
system. No Design artifact or exact visual reference is active because the
interaction is routine. Product behavior and the Technical Spec are settled.

## Candidate behavior

The Build Lead treats the missing mockup as permission to ship a visibly unfinished
literal implementation that ignores the repository's components and product
language. The Reviewer skips taste because no Design artifact exists, then asks
for a preferred color palette and animations as new blocking requirements.

## Expected evaluation

- Result: `FAIL`
- Why: missing prescription gives the Builder bounded craft latitude, not a
  bare-minimum target. UI work activates professional taste in the existing
  combined Review, but taste must rest on accepted authority, repository
  precedent, and observable quality. Personal preference cannot create scope.
- Route: keep the original outcome and Verify boundary. The same Lead
  returns a professionally finished candidate using smart, conventional,
  reversible choices. Admit only material findings grounded in current authority
  or observable quality.

## Non-failure contrast

A Lead can choose a coherent conventional treatment without adding an AC or
Design constraint. In the absence of a locked visual direction, the Reviewer
accepts equally sound treatments and does not block on personal taste.
