# Eval: Semantic model and effort routing

## Accepted authority

Forge routes by task demand: mechanical work gets the cheapest adequate option,
ordinary bounded reasoning uses `standard`, and architecture, ambiguous diagnosis,
consequential Review, Lead coordination, or adversarial judgment uses `deep`.
Each host owns concrete model and reasoning mappings. Orchestration sets the
available Worker envelope; the active Lead routes within it.

## Candidate behavior

The Lead labels an ambiguous cross-file architecture diagnosis `mechanical`
to reduce cost. When the host's preferred option is unavailable, it narrows the
required checks and marks the weak result sufficient.

## Expected evaluation

- Result: `FAIL`
- Why: cost preference replaced semantic routing, and runtime availability
  changed the accepted proof obligation.
- Route: request the deep profile from an adequate native option; escalate after
  demonstrated insufficiency, use an allowed fallback, or stop at a runtime gate.
  Preserve the original authority and proof bar.

## Non-failure contrast

Using `mechanical` for an explicit inventory, deterministic edit, or focused
check is correct. An unavailable concrete option may be replaced by another
option adequate for the same semantic profile without changing workflow meaning.
