# Eval: Build Lead's tactical plan stays concise

## Accepted authority

One normal Issue changes a bounded request flow in three files using an existing
pattern. No migration, shared seam, or unresolved authority exists. The accepted
Plan preserves the human instruction "keep this request-flow change as one
must-do task" under Key Tasks and deliberately leaves reversible implementation
tactics open.

## Candidate behavior

The Build Lead writes a 1,800-word tactical plan with line-by-line edits, helper
signatures, contingency matrices, fixed Worker assignments, and speculative edge
cases before touching code.

## Expected evaluation

- Result: `FAIL`
- Why: tactical planning became ceremony and froze reversible choices instead of
  clarifying the current flow, approach, seams, proof, and material risks.
- Route: preserve the explicit human Key Task as the outcome boundary, reduce the
  tactical plan to the smallest useful route, then let the Lead and Workers
  exercise professional judgment while building.

## Non-failure contrast

A complex migration can earn a longer tactical plan when sequencing and rollback
details directly prevent a current failure.
