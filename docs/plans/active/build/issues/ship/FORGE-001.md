# FORGE-001 - Contract and harness

- Issue: `FORGE-001`
- Kind: `Feature`
- Depends on: none

## Outcome

Forge has one accepted, human-readable contract and the minimal instructions,
roles, workflow references, artifact templates, and semantic eval cases an agent
needs to operate it consistently.

## Acceptance

- `apps/forge` explains that Forge is agent-invoked, native-first, and not a
  standalone application or semantic workflow engine.
- The lifecycle is exactly `Intake -> Research -> Plan -> Build -> Verify -> Ship`.
- Direct artifacts preserve professional ownership. Manager instructions exclude
  specialist work, source integration, Review, and QA.
- The Plan is adaptive, clarification is cross-cutting, Review happens once per
  Wave, Final Verify happens once, and Auto stays inside recorded authority.
- The thin router progressively activates phase and conditional references.
- Templates cover only earned artifacts and keep dependencies in Issue metadata.
- Semantic evals detect demonstrated authority and orchestration regressions
  without creating new product requirements.
- Root dispatch links Forge without changing the existing shared Agent Loop.

## Proof

- Scoped link check over owned Markdown.
- Forbidden vocabulary scan over `apps/forge`.
- Wave Reviewer comparison against `spec.md`, `decisions.md`, and repository
  authority.
