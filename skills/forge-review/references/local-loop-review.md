# Local Forge loop review

Use the selected loop's existing Issue, accepted sources and decisions, Build
record, previous Review returns, and proof. Keep their current locations and
record owner; do not create a second loop or require a new Spec to review an
already bounded assignment. Resolve the application separately from loop storage.

Pin the actual comparison base and complete candidate, including dirty and
relevant untracked files. A branch label alone does not capture the Builder's
working state. Give the independent Reviewer a stable inspectable candidate and
independently retained accepted authority. Prevent concurrent source edits through
existing ownership; a stopped Builder and fixed candidate can be reviewed
read-only in the same checkout. Use a frozen snapshot or separate copy only when
the host needs it for access or concurrent work. Inspect previous findings and relevant new log entries, then judge
the whole current assignment rather than only its repair list.

Follow [Independent Review](review.md) for coverage, staffing, evidence, admission,
and verdict. Preserve original returns and dispositions in the existing loop
record using the [review template](../assets/review.md) when earned. The record
owner persists the read-only Reviewer's return. Direct Review stops there;
Build resumes repairs only under its own existing authorization.
