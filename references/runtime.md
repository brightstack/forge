# Runtime and delegation

Forge runs inside one hosting coding agent and uses that host's native subagents.
Forge describes the outcome, professional perspective, clean-context independence,
write ownership, and evidence; the host owns spawning, scheduling, tools, and
permissions. Forge has no provider adapter or subprocess agent fallback. If the
host cannot provide required independent context or evidence, report the gap.

Every professional/helper packet includes [authority](authority.md), the relevant
[finding admission](severity.md) or [repair](repair.md) procedure when needed, and
the [return contract](returns.md). Use [target harness resolution](target-harness.md)
to supply the actual maps the `forge context` rule selects, routed standards, exemplars, and
check paths. Receiving agents read those sources; a persona/helper or owner
summary cannot replace them.
The accountable owner inspects the returned artifact and relevant new log evidence
before advancement.

## Accountabilities

- **Coordinator:** owns Launch, requested boundary, authority, current state, and
  phase composition using [workflows](workflows.md).
- **Professional owner:** Product Manager, Designer, Engineer, Architect,
  Researcher, Reviewer, or QA perspective accountable for a phase result.
- **Engineer:** owns tactical planning, implementation, required Worker
  delegation, integration, internal review, and repairs. A separate Engineer
  assignment owns authorized Simplify after passing Build/Review, before QA;
  changed results receive affected proof and independent delta Review.
- **Reviewer:** owns the read-only integrated candidate verdict in a separate context.
- **Verify owner:** a clean-context QA professional exercises the actual outcome.
- **Explorer / Worker / Judge:** temporary helpers. They investigate, produce a
  bounded outcome, or inspect one dimension; a Judge owns its dimension report and
  verdict, never integration or the final Review/Verify verdict.

Use the [concrete workflow assignments](workflows.md#concrete-staffing). These are
native subagent jobs, not multiple personas adopted by the Coordinator. A Quick
ready Issue without additional triggers uses Engineer and Reviewer. Spec
specialists follow [specialist sequence](workflows.md#specialist-sequence). Do
not spawn Product Manager, Designer, and Architect together. Parallelize other
work when it is read-only or writes do not overlap; one accountable owner
integrates all returns. Keep useful subagents across repair follow-ups while their context
stays focused. Judge Review independence by separate relevant context, read-only
ownership, pinned authority and candidate, and checked evidence. A different
provider, model family, or lineage is not required. Never claim clean context,
browser access, or independence the host did not provide.

## Model selection

Before each new native assignment, resolve the active engine's optional defaults
from the target application's `forge.yml` with
`forge config resolve --repo <target> --engine <actual-engine> --role <role>`.
Use `worker` for Worker, `reviewer` for Reviewer, `judge` for Judge, and `main`
for other professionals/helpers. Pass any explicit current user model and effort
as separate `--model` and `--effort` arguments, including a user choice scoped to
this assignment. Never copy values from another engine's section.

Resolve model and effort independently: explicit current user field, configured
role field, configured `main` field, then orchestration discretion. A role that
sets only model inherits the configured main effort; a role that sets only effort
inherits the configured main model. Omitted settings leave that field to the
orchestrator. See [configuration and storage](cli.md#configuration-and-storage)
for the optional schema and inspection output.

Inspect the current host's exposed native model IDs, effort values, supported
pairs, and dispatch controls. Validate the resulting pair, including inherited
fields, before dispatch. Pass the resolved fields through those native controls
when available. If a selected value/pair is unsupported or the host cannot apply
it, report the specific gap and hold that assignment until an authorized valid
choice is available. Do not translate IDs, silently change effort, borrow another
engine's settings, or claim an override the host did not apply. Host permissions
and actual capabilities remain controlling.

Record the actual agent ID, role, resolved model/effort and each field's source
from inspection in the existing assignment/log evidence. Distinguish requested
values from host-confirmed effective values and retain any capability gap. The
CLI resolves defaults; it never launches an agent. `main` is a default for new
dispatches and does not switch the already-running Coordinator's host model.
Parsing configuration alone does not prove native dispatch support.

When a field remains discretionary, the host's current model is a sensible default.
Choose proportionately: a fast economical model can extract a bounded fact, update
a local mechanical seam, or run a focused check; stronger reasoning fits ambiguous
architecture, cross-boundary integration, or a difficult Review. A small patch may
use the current model throughout. An API and database contract change may assign
stronger reasoning to the Builder and relevant Review lenses. A focused regression
review may use a faster model when the authority, candidate, and reproduction are
already crisp. Deterministic claims still come from tools and executed checks.

An independent Reviewer may use the same model family as the Builder when the
context and capability meet the Review contract. Do not invent model equivalence
or availability, hard-code a provider default, or use maximum effort for every
task. Configuration adds optional defaults without changing staffing,
independence, authority, or the requested phase boundary.

For Review, use its own judge selection and the shared [staffing triggers](workflows.md#concrete-staffing).
The Reviewer covers dimensions directly or dispatches required Judges
with clean, read-only contexts and the exact authority/candidate packet. Preserve
delegated reports, record Reviewer-owned assessments, and resolve conflicts from
evidence rather than votes. Staffing changes do not waive applicable coverage,
required independence from Build, or Verify.
